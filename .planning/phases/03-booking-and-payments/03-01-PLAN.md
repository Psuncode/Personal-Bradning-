**BUG-01 fix in `src/lib/serverCalendar.ts`:**

In the `_fetchServerAvailability` function (around line 152-165), the day bucketing loop uses `startOfDay(day)` and `endOfDay(day)` which operate in the Node.js system timezone (UTC on Vercel). This causes all-day CalDAV events with UTC midnight boundaries to be bucketed to the wrong Mountain Time day.

Replace the existing day bucketing logic:

```typescript
// BEFORE (broken — uses system timezone for day boundaries):
const dayStart = startOfDay(day);
const dayEnd = endOfDay(day);
const dayEvents = events
  .filter(
    (e) => new Date(e.endTime) > dayStart && new Date(e.startTime) < dayEnd
  )
  .map((e) => ({
    startTime: new Date(e.startTime),
    endTime: new Date(e.endTime),
  }));
```

With timezone-aware bucketing:

```typescript
// AFTER (correct — converts event times to Mountain Time before comparing):
import { toZonedTime } from 'date-fns-tz';  // add to existing imports from date-fns-tz

const TIMEZONE = 'America/Denver';

// In the while loop:
const dayInMT = toZonedTime(day, TIMEZONE);
const dayStartMT = startOfDay(dayInMT);
const dayEndMT = endOfDay(dayInMT);

const dayEvents = events
  .filter((e) => {
    const eventStartMT = toZonedTime(new Date(e.startTime), TIMEZONE);
    const eventEndMT = toZonedTime(new Date(e.endTime), TIMEZONE);
    return eventEndMT > dayStartMT && eventStartMT < dayEndMT;
  })
  .map((e) => ({
    startTime: new Date(e.startTime),
    endTime: new Date(e.endTime),
  }));
```

Also add `toZonedTime` to the existing `import { format } from 'date-fns-tz'` line — change to `import { format, toZonedTime } from 'date-fns-tz'`.
