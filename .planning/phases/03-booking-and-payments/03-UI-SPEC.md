## Spacing Scale

Declared values (all multiples of 4 — 8-point scale):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, step indicator dot spacing |
| sm | 8px | Inline element gaps, between slot buttons |
| md | 16px | Default element spacing, input padding |
| lg | 24px | Step section padding, card inner padding |
| xl | 32px | Between form sections within a step |
| 2xl | 48px | Between major sections on page |
| 3xl | 64px | Page top/bottom padding |

Exceptions:
- Calendar day cells: `p-2` (8px all sides) — matches BookingForm.tsx pattern
- Time slot buttons: `p-3` (12px) — consistent with BookingForm.tsx; acceptable as 4px multiple
- Touch targets (all interactive elements): minimum 44×44px per ui-ux-pro-max §2 `touch-target-size`
- Step indicator: 32px diameter circles, 8px gap between dots

| Secondary (30%) | `byu-gray` | #F5F5F5 | Step container background, disabled calendar cells, form section dividers |

| Accent light | `byu-sky` | #C5E3F6 | Calendar hover backgrounds (`bg-byu-sky/20`), active slot borders |

| Dark text | `byu-dark-gray` | #4A4A4A | Body copy, helper text, secondary labels |
| Destructive | `destructive` (oklch 0.577 0.245 27.325 ≈ #DC2626) | — | Error banners only (CalDAV load failure, Stripe error) |

Accent (`byu-navy`) reserved for:
1. Selected calendar day cell background
2. Selected time slot button background + border
3. Primary CTA buttons ("Continue", "Proceed to Payment")
4. Step indicator — completed step fill
5. Step heading text color (`text-byu-navy`)
6. Navigation month arrows (text color)
7. "Book Now" button on pricing cards (Phase 3 addition)
8. Input focus ring (`focus:border-byu-navy`)

Accent NOT used for: unselected slot borders, body text, background fills, decorative elements.

Success state: `bg-green-50 border-green-200 text-green-700` — matches BookingForm.tsx confirmation pattern; do not introduce a new success semantic color.

Warning state: `bg-yellow-50 border-yellow-200 text-yellow-700` — CalDAV availability warning; matches BookingForm.tsx.

Source: BYU tokens from globals.css; usage rules derived from BookingForm.tsx patterns + 60/30/10 allocation.

## Layout Contract

### `/photography/book` — Booking Form Page

```
Page: max-w-2xl mx-auto px-6 py-16
  H1 (Playfair Display 36px): "Book a Session"
  Step indicator (4 steps horizontal)
  ─────────────────────────────────
  [Step content panel — white bg, rounded-xl, border border-gray-200, p-8]
    Step heading (Inter 24px 600 text-byu-navy)
    Step body
  ─────────────────────────────────
  Navigation buttons row (justify-between)
    [Back — outline] [Continue / Proceed to Payment — primary]
```

Step indicator: 4 numbered circles (28px) connected by a horizontal line. Completed = `bg-byu-navy text-white`. Current = `bg-byu-light-blue text-white ring-2 ring-byu-navy/30`. Future = `bg-gray-200 text-gray-500`.

Steps (in order):
1. Package Selection — dropdown + card preview showing name, duration, price, deposit
2. Date — calendar grid (7-col, re-uses renderCalendar pattern from BookingForm.tsx)
3. Time Slot — 3-column grid of time buttons
4. Your Details — name (required), email (required), notes (optional textarea)

After step 4: "Proceed to Payment" → Stripe Checkout hosted redirect (no inline card form).

## Accessibility Contract

Applies ui-ux-pro-max §1 (CRITICAL) and §8 `multi-step-progress`:

- **Contrast**: `byu-navy` (#002E5D) on white = 12.6:1 — passes WCAG AAA. `byu-dark-gray` (#4A4A4A) on white = 9.7:1 — passes WCAG AAA.
- **Focus rings**: All interactive elements have visible 2px focus ring using `ring-2 ring-byu-navy ring-offset-2`. Never remove focus rings.
- **Step indicator**: `aria-current="step"` on active step circle. Completed steps use `aria-label="Step {N}: {Step Name} — complete"`.
- **Calendar navigation**: Month prev/next buttons have `aria-label="Previous month"` / `aria-label="Next month"` — already present in BookingForm.tsx.
- **Disabled calendar days**: `disabled` attribute + `aria-disabled="true"` on `<button>` elements.
- **Form labels**: Every input has a visible `<label>` with `htmlFor` — no placeholder-only labels (ui-ux-pro-max §8 `input-labels`).
- **Error placement**: Validation errors appear below the relevant field as `role="alert"` text (ui-ux-pro-max §8 `error-placement`, `aria-live-errors`).
- **Loading state**: "Proceed to Payment" button shows `disabled` + `<Loader2 className="animate-spin" />` icon during Stripe session creation (ui-ux-pro-max §2 `loading-buttons`).
- **Touch targets**: All slot buttons and calendar day cells meet 44×44px minimum. Slot button grid is `gap-2` (8px) — meets 8px spacing minimum.
- **Keyboard navigation**: Tab through steps follows logical DOM order. Calendar supports arrow-key navigation within the grid (add `onKeyDown` handler).
- **Heading hierarchy**: Page uses H1 → H2 (step heading) — no level skip.
- **prefers-reduced-motion**: Step transition (opacity fade) must check `window.matchMedia('(prefers-reduced-motion: reduce)')` and skip animation if true.

## Animation Contract

Applies ui-ux-pro-max §7 `duration-timing`, `transform-performance`, `state-transition`:

| Interaction | Effect | Duration | Easing |
|-------------|--------|----------|--------|
| Step transition (forward) | `opacity: 0→1` + `translateX(16px→0)` | 200ms | ease-out |
| Step transition (back) | `opacity: 0→1` + `translateX(-16px→0)` | 200ms | ease-out |
| Button press | `scale: 1→0.97` | 100ms | ease-in-out |
| Calendar cell hover | `bg-byu-sky/20` color transition | 150ms | ease-out |
| Slot button select | border + bg color transition | 150ms | ease-out |
| Package card select | border + ring color transition | 150ms | ease-out |
| Loading spinner (Stripe session) | `animate-spin` on Loader2 icon | continuous | linear |
| Month navigation (calendar) | `opacity: 0.6→1` | 150ms | ease-out |

Only `transform` and `opacity` are animated — no width/height/top/left changes (ui-ux-pro-max §7 `transform-performance`).

## Form Validation Contract

Applies ui-ux-pro-max §8 `inline-validation`, `error-clarity`, `focus-management`:

| Field | Validation rule | Error message |
|-------|----------------|---------------|
| Name | Required, min 2 chars | "Please enter your name." |
| Email | Required, valid email format | "Please enter a valid email address." |
| Package | Required (auto-selected if ?pkg= param present) | "Please select a package to continue." |
| Date | Required (must select before advancing step 2→3) | (step advance blocked; no inline error — "Continue" disabled) |
| Time slot | Required (must select before advancing step 3→4) | (step advance blocked; "Continue" disabled) |

Validation fires on blur for text inputs, not on keystroke (ui-ux-pro-max §8 `inline-validation`).
On submit of step 4 ("Proceed to Payment"), if fields are invalid: focus moves to first invalid field automatically (ui-ux-pro-max §8 `focus-management`).
